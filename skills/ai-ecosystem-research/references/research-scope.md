# 研究覆盖与筛选

九层为完整生态周报／月报的覆盖清单；专题只选与研究问题相关的层，不以未覆盖其他层判失败。下述榜单数量与七日窗口是周报默认值；月报与专题按模式模板调整。厂商与工具名是发现种子，须随实际生态扩展、替换，不能成为封闭白名单。

## 来源发现

先访问平台公开列表、官方新闻／更新日志，再展开关键词检索。通用检索不得仅限 Agent/RAG 等既定方向；至少考虑语言、音频、视觉／视频、空间／机器人、基础设施与应用的非预设线索。中文与英文检索并用。记录查询、日期、命中及失败；搜索引擎覆盖不足不代表生态没有事件。

代码优先查看 release tag/commit 下的文件；识别维护者源码、社区包装、量化衍生版本和同名项目。不同 fork 不自动算独立创新或跨社区验证。

## 项目七问

页首：名称、官网、仓库、类别、作者、首次发布／本期事件、技术栈、热度口径和采集日期。

1. 它是什么：功能、用户、实际问题。
2. 为什么热门：新技术、传播、需求、争议分别列证据；无热度证据就不称突然爆红。
3. 架构是什么：模块→数据流→执行模型；注明源码文件、版本、来源和推断。
4. 本质区别：选 2–3 个代表替代方案，同一维度对比，区分实现差异与未经测量的性能。
5. 宣传实现了吗：Demo、代码、Benchmark、Issue、复现逐项判断，避免以 README 代替验证。
6. 反映什么机制：明确能迁移的方法、适用条件、不能外推的边界。
7. 后续观察什么：具体文件／发布／测试／反馈信号、回访时间。
