# 核实、研究完成与交付

研究开始与最终验收时读取。本规则适用于周报、月报和专题；不固定项目、日期、结论或宿主工具。

## 不确定性不是统一的停止理由

| 类型 | 处理 |
|---|---|
| 尚未查阅 | 内部任务，继续查阅；不能作为正文采用边界 |
| 入口失败／过期缓存 | 改查直接页面、原始文件、官方 API、定日记录或作者发布；记录结果 |
| 来源冲突 | 核对版本、事件时间、定义与原始制品；未解决的实质冲突保留双方 |
| 公开未披露 | 查过合理权威入口后说明具体未披露字段，避免声称证明不存在 |
| 必须实验才能回答 | 先报告文档／源码已能确认的内容；只有运行行为或独立性能需要实验 |
| 未来结果 | 给有期限的可观察信号，不冒充已发生事实 |

停止研究某个问题须写明具体缺失项、已走路径、失败原因、结论影响与替代证据。不存在统一“查两次即可”的次数豁免；当新增检索重复且合理入口已用尽时停止，不无限检索。时间到了、篇幅够了、已有免责声明都不是完成依据。

## 按主张找证据

| 要回答的问题 | 首选证据与后续检查 |
|---|---|
| 它是什么、输入输出是什么 | 官方文档、接口、例子与实际制品；目录标签只作发现 |
| 何时发布、此次变了什么 | 公告、tag、commit、论文版本；区分首次发布与后续更新 |
| 架构与约束 | 模型配置、调用链、依赖、关键源码；标明文件与版本 |
| 性能与成本 | 原始实验、硬件、任务、基线、计量范围；厂商结果注明归属，不必因未独立复现而删去可核查结果 |
| 热度与采用 | 平台定义、采集范围、讨论原帖与具体用户证据；不能用传播证明收益 |
| 历史变化 | 固定历史版本与同口径新证据；缺历史不得从现值臆算增长 |

重点对象入正文前，必须能回答具体用途、输入输出、交付物、关键约束、入选事件及时间依据。基本身份不清楚者留在内部候选，不以“需先辨别”填表。厂商与社区检索覆盖全局后再定主线；同厂商数项小更新不能代替全球格局。不能以截止后新品填补本期章节。

## 阅读深度与论述深度相配

普通条目应给可直接理解的功能事实和有根据的适用判断；“检查成本/关注安全/待验证效果”不能充当全部分析。重点深析须解释机制、关键实现和至少两个具体可比方案；只有摘要／模型卡则继续读全文／源码／接口文档，闭源时准确称接口或公开机制分析。

每条核心事实在 evidence.json 绑定具体 claim、URL、标题、归属、事件时间、查阅时间与 locator（章节/字段/代码路径）。建立 report-claims.json 将报告论点映射到 evidence_ids。记录 URL 可访问不等于证据支持结论。分析说明由哪些事实推出、有何竞争性解释。

## 研究验收与发送是两道门

保存 acceptance.json：mode、artifact_status（draft/ready）、requirements（id/status/evidence/reason）、unresolved（question/type/attempts/impact/blocking）、delivery_ready。证据记录与文件检查不能替代语义审查。

- 尚未查阅、可解决但未做的核验、主体时间窗错误、基本项目介绍不足、仅摘要却称深析、关键主张没有支持证据：blocking=true，draft，delivery_ready=false。
- 数据确实无法恢复或公开不披露，可在完成合理替代核验后列为来源限制。结论收窄并仍完成本模式主要研究任务，才可 ready；不能仅增加“有限覆盖”标签绕过研究缺口。
- 周报验收发现覆盖、各榜单真实口径、项目导读和深析；月报另验历史集合、前后证据、判断修正与原预测不变；专题验问题是否被机制与证据回答。
- 已授权发送的任务也必须检查 delivery_ready；未通过就保存草稿并明确未投递，不能发送后把失败解释留给读者。不因为验收失败新建外部服务、仓库或调度。
- 最终正文以已确认的事实和有依据的判断为主，限制集中表达，仅在影响局部决策时再次说明。预测的不确定性不应污染已知功能事实。

修订保留旧稿及修订记录。重做不能只改措辞或将“待确认”改成肯定句；须实际补证、更换对象、纠正结论或移除不能支持的主张。

投递前运行 `python <skill>/scripts/check-delivery.py <run-dir>`。该脚本阻止缺少验收、证据字段、论点映射和未完成研究的投递，不证明内容真实；语义与实际页面检查仍须完成。

验收 requirements 使用稳定键：所有模式包括 source_support、time_scope、reader_value、semantic_review、visual_review；周报／月报另有 nine_layers、rankings；月报另有 longitudinal_review、judgment_revision，且 review.json 非空；专题使用 research_question。每项 evidence 指向实际检查记录，不能把自报 pass 当证据。

发现入口需有替代路径：分页／分时获取窗口帖子并检查重复和边界；模型与项目目录回到发布者 README、配置和制品；榜单镜像标明平台与采集时点；平台日期归档不匹配时不得套用当前页。不要把标题关键词样本称全站分类。对争议读取维护者后续回复，对旧项目回访实际页面变化。

验收要检查报告整体研究价值：是否被单厂商小更新支配，是否遗漏可查的大类，产品是否让首次读者理解输入输出，数据分析是否说明分母／单位／基线，深析是否读到失败与成本。已知问题须补证或重选对象，不能只加免责声明。
